# Инструкции агента Makecom

## Начать здесь
1. scope-of-work.md — исходное ТЗ; не редактировать.
2. docs/work-plan.md — актуальный порядок пользователя, текущий этап и передача контекста.
3. docs/acceptance-checklist.md — требования FR/NFR, критерии и фактические проверки.
4. docs/architecture.md — действующее устройство проекта и ограничения.
5. docs/agent-workflow.md — алгоритм работы; docs/agent-activity-log.md — история действий.

## Правила
- Проверять git status, сохранять посторонние изменения и пользовательские данные.
- Работать по текущему этапу; последние указания пользователя выше старых документов.
- CompanyCore — источник фактов, сайты используют отдельные снимки и версии.
- Согласованность содержания, разнообразие и перевод задаются модели до генерации; не добавлять последующие смысловые оценщики/платные исправления.
- Техническая схема ответа, очистка HTML/CSS, контроль бюджета и доступов обязательны.
- Ключ OpenRouter — только зашифрованная HttpOnly session cookie; сервер использует его временно. Никаких ключей в логах, экспорте, сайтах, коммитах.
- Проект должен работать локально без Render/Supabase; подключение БД — отдельная задача этапа 4.
- Перед изменением кода читать затрагиваемые разделы, проверять результат подходящими тестами/сборкой/типами.
- Не развёртывать, не публиковать, не создавать облачные ресурсы и не выполнять разрушительные действия без явного поручения.
- Платную генерацию проверять только на соответствующем этапе с подключённым пользователем токеном.
- Обновлять журнал, чек-лист и передачу контекста в docs/work-plan.md. Новые дублирующие документы не создавать.

Исторические материалы объединены в docs/archive/development-notes.md; они не задают текущие правила.
