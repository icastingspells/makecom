## Решения пользователя

- Качество содержания закладывается в запрос модели: факты, согласованность, неповторяемость, структура, перевод, телефон и город. Не строить после ответа отдельную смысловую проверку/оценку похожести/второй запрос для исправления.
- Сохранить техническое чтение JSON/схемы, безопасную подстановку фактов и очистку HTML/CSS, контроль бюджета и доступов. Это не оценка качества текста. Модель может ошибаться; промпт не является доказательством достоверности.
- Файл scope-of-work.md не редактировать. Чек-лист учитывает его и последующие уточнения.
- Проект должен полноценно работать локально без Supabase и Render. SQLite реализована встроенным node:sqlite через IStorage; файловый и Supabase-адаптеры сохранены. Рабочий server/.env не менялся: библиотека остаётся в JSON до явного импорта. Не называть JSON-файлы базой данных.
- Сохранить библиотеку и старые сайты. Не удалять данные, ключи и пользовательские изменения при чистке. Перенос данных в новую БД должен быть явным и проверенным.
